# Requirement-by-requirement solution choices and plans

See [the analysis](ANALYSIS.md) for the timeline, exact error lines, reproductions,
primary references and all 16 best-practice decisions. This table records the
alternatives considered and the implemented sequence for each issue requirement.

| Requirement / problem | Possible approaches | Chosen solution plan and completion evidence |
| --- | --- | --- |
| Understand the five named main runs and every comment | Inspect status badges alone; or preserve source-correlated metadata and raw logs. | Fetch issue and all PR comment/review endpoints with pagination; collect runs, timestamps, SHAs, jobs and logs; inspect bounded chunks; classify historical vs current outcomes. `github/`, `ci-logs/` and diagnostic indexes preserve the evidence. |
| Download all related logs into the requested directory | Link to expiring hosted logs; or preserve reproducible local snapshots. | Save complete downloadable runs since October 3, available job logs for unfinished runs, related PR 108 authenticated Gist sessions, local probes and analyzer API/browser evidence. Add reusable collector and SHA-256 manifest/index generator. |
| Remove C++ build errors | Change Clang/Ubuntu versions; create a complete C++ implementation; or remove unsupported automation. | Verify LLVM repository mismatch and absent CMake/source/release metadata; retain the placeholder; remove its fictitious build/release workflow; document actual prerequisites; reject future phantom build configuration. No implemented language is removed. |
| Prevent benchmark false successes | Require job success alone; or validate the complete artifact contract as well. | Write failing empty/schema/variant tests; bound inputs; plan one matrix; pin one merge base; fail absent uploads; download fresh artifacts; verify all filenames, variants, operations, SHA and merge tree before reporting or publishing. Eight real cells and regression tests exercise both languages/categories/widths. |
| Prevent stale or racing publication | Blind rebase/retry; serialize alone; or serialize plus revalidate/regenerate. | Reproduce a real bare-Git concurrent write and changed-source rejection; use one non-cancelling main writer group; fetch main and reject changed measured sources; create a fresh worktree and regenerate on each finite retry; retry only proven branch races and retain actual protection/authentication errors. |
| Make failure/cancellation status truthful | Treat every cancellation as failure; accept all cancellations; or verify the configured reason. | Add terminal gates to every maintained test/audit workflow; fail failures, unknown outcomes and current-run cancellation; accept only superseded readers with an enabled cancellation policy and a changed remote head. | Compare every file in all three templates | Copy scaffolding blindly; or inventory every file and apply relevant CI semantics. | Preserve full trees and exact revisions; classify every tracked file; review workflows/scripts/configuration; map every best-practice principle to an implementation or concrete delivery-target limitation. | Reuse applicable quality/security practices everywhere | Depend on external analyzers only; or enforce matching local and hosted checks. | Pin action SHAs and runners; restrict permissions; set time budgets; validate current merge trees; add Ruff/mypy/Bandit, actionlint/ShellCheck/zizmor, all-crate Rust/C# formatting, strict builds, Markdown/per-document sections/links, line limits, secretlint and optional pre-commit hooks. | Finish everything in PR 111 without rewriting history | Work on main or force-push; or preserve atomic commits and the prepared PR. | Commit source steps, merge current main, commit evidence, push only the prepared branch, update title/body, review the PR diff, inspect every latest-head check and failed log, then mark ready. No package version/release trigger applies because no distributable registry/image target exists. |

The final review also reproduces Bandit's nested-call unused-annotation warning,
uses separate assignments to retain the exact security check without warnings,
and adds current-version evidence and a fix suggestion to existing Bandit #1041.

Hosted implementation checks are preserved separately from the original failing
runs. Final branch checks must be inspected at the actual pushed head; a passing
older source revision is never used as proof that a newer revision passes.
